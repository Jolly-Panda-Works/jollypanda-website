# چک‌لیست سئو — استودیو جولی پاندا

یک چک‌لیست عملی و گام‌به‌گام برای اجرا **پس از** استقرار (deploy) سایت `jollypanda.ir`. هر بخش را از بالا به پایین انجام دهید و پس از تکمیل، تیک بزنید.

---

## ۱. راه‌اندازی موتورهای جستجو

### - [ ] ۱.۱ راه‌اندازی Google Search Console
- **هدف:** دادن دید مستقیم به گوگل نسبت به نحوه ایندکس و عملکرد سایت.
- **چرا مهم است:** اصلی‌ترین کانال برای وضعیت ایندکس، خطاهای خزش و اقدامات دستی گوگل است.
- **مراحل:**
  1. به [search.google.com/search-console](https://search.google.com/search-console) بروید.
  2. `jollypanda.ir` را به‌صورت **Domain property** اضافه کنید (پوشش‌دهنده http/https و www/non-www).
  3. مالکیت را از طریق رکورد DNS TXT در پنل ثبت‌کننده دامنه تایید کنید.
  4. مطمئن شوید وضعیت "Ownership verified" نمایش داده می‌شود.
- **ابزارهای پیشنهادی:** Google Search Console، پنل DNS ثبت‌کننده دامنه.
- **نتیجه مورد انتظار:** پراپرتی تایید‌شده و دریافت داده‌های خزش/ایندکس طی ۲۴ تا ۴۸ ساعت.

### - [ ] ۱.۲ راه‌اندازی Bing Webmaster Tools
- **هدف:** ایندکس شدن سایت در Bing/Yahoo/DuckDuckGo (که از ایندکس Bing استفاده می‌کند).
- **چرا مهم است:** Bing همچنان ترافیک قابل‌توجهی دارد و DuckDuckGo به آن متکی است.
- **مراحل:**
  1. به [bing.com/webmasters](https://www.bing.com/webmasters) بروید.
  2. سایت را مستقیماً از Google Search Console وارد کنید (سریع‌ترین روش) یا از طریق DNS/متا‌تگ تایید کنید.
  3. `sitemap.xml` را از بخش Sitemaps ارسال کنید.
- **ابزارهای پیشنهادی:** Bing Webmaster Tools.
- **نتیجه مورد انتظار:** سایت تایید و سایت‌مپ بدون خطا پذیرفته شود.

### - [ ] ۱.۳ ارسال Sitemap
- **هدف:** اطلاع‌رسانی دقیق به موتورهای جستجو درباره URLهای موجود و اهمیت هرکدام.
- **چرا مهم است:** سرعت کشف صفحات جدید/به‌روزشده را افزایش می‌دهد.
- **مراحل:**
  1. مطمئن شوید `https://jollypanda.ir/sitemap.xml` بارگذاری می‌شود و XML معتبری است.
  2. آن را هم در Google Search Console و هم در Bing Webmaster Tools ارسال کنید.
  3. با اضافه شدن صفحات جدید، دوباره ارسال کنید.
- **ابزارهای پیشنهادی:** Google Search Console، Bing Webmaster Tools، [XML Sitemap Validator](https://www.xml-sitemaps.com/validate-xml-sitemap.html).
- **نتیجه مورد انتظار:** وضعیت سایت‌مپ "Success" و کشف هر ۳ آدرس.

### - [ ] ۱.۴ بررسی robots.txt
- **هدف:** اطمینان از اینکه خزنده‌ها اجازه دسترسی به سایت و یافتن سایت‌مپ را دارند.
- **چرا مهم است:** تنظیم نادرست robots.txt می‌تواند به‌طور ناخواسته کل سایت را از دید موتورهای جستجو مسدود کند.
- **مراحل:**
  1. به `https://jollypanda.ir/robots.txt` مراجعه کنید و از پاسخ `200 OK` مطمئن شوید.
  2. مطمئن شوید شامل `Allow: /` و خط `Sitemap:` صحیح است.
  3. آن را در گزارش robots.txt سرچ‌کنسول تست کنید.
- **ابزارهای پیشنهادی:** تستر robots.txt در Google Search Console.
- **نتیجه مورد انتظار:** هیچ صفحه‌ای به‌اشتباه مسدود نشده باشد.

### - [ ] ۱.۵ درخواست ایندکس
- **هدف:** درخواست دستی از گوگل برای خزش و ایندکس فوری صفحات کلیدی.
- **چرا مهم است:** بدون آن، ایندکس اولیه می‌تواند روزها تا هفته‌ها طول بکشد.
- **مراحل:**
  1. در Search Console، از **URL Inspection** برای `/`، `/services.html` و `/about.html` استفاده کنید.
  2. برای هرکدام روی **Request Indexing** کلیک کنید.
  3. همین کار را برای Bing از طریق "Submit URLs" در Bing Webmaster Tools تکرار کنید.
- **ابزارهای پیشنهادی:** Google Search Console، Bing Webmaster Tools.
- **نتیجه مورد انتظار:** هر سه صفحه طی چند روز به‌عنوان ایندکس‌شده نمایش داده شوند.

## ۲. اعتبارسنجی شبکه‌های اجتماعی و متادیتا

### - [ ] ۲.۱ اعتبارسنجی Open Graph
- **هدف:** اطمینان از نمایش صحیح پیش‌نمایش لینک در فیسبوک، لینکدین، تلگرام، واتس‌اپ و غیره.
- **چرا مهم است:** پیش‌نمایش خراب باعث کاهش نرخ کلیک هنگام اشتراک‌گذاری لینک می‌شود.
- **مراحل:**
  1. هر آدرس صفحه را در [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) و [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/) تست کنید.
  2. مطمئن شوید `og:title`، `og:description` و `og:image` درست نمایش داده می‌شوند.
  3. پس از هر تغییر، از "Scrape Again" برای به‌روزرسانی کش استفاده کنید.
- **ابزارهای پیشنهادی:** Facebook Sharing Debugger، LinkedIn Post Inspector.
- **نتیجه مورد انتظار:** عنوان، توضیح و تصویر ۱۲۰۰×۶۳۰ صحیح، بدون هشدار.

### - [ ] ۲.۲ اعتبارسنجی Twitter Card
- **هدف:** اطمینان از نمایش صحیح کارت `summary_large_image` در X (توییتر).
- **چرا مهم است:** ابزار اعتبارسنجی رسمی توییتر حذف شده، بنابراین باید از ابزار شخص ثالث یا ارسال لینک تستی استفاده کرد.
- **مراحل:**
  1. مطمئن شوید متاتگ‌های `twitter:card`، `twitter:title`، `twitter:description` و `twitter:image` در همه صفحات وجود دارند.
  2. از یک ابزار پیش‌نمایش شخص‌ثالث (مثل [cardpreview.dev](https://cardpreview.dev/)) استفاده کنید.
  3. یک لینک واقعی (یا پست پیش‌نویس) ارسال کنید تا نمایش داخل اپ تایید شود.
- **ابزارهای پیشنهادی:** cardpreview.dev، ارسال پست تستی.
- **نتیجه مورد انتظار:** کارت با تصویر بزرگ و عنوان/توضیح صحیح نمایش داده شود.

## ۳. عملکرد و Core Web Vitals

### - [ ] ۳.۱ ممیزی Lighthouse
- **هدف:** دریافت امتیاز پایه و عینی برای Performance، SEO، Accessibility و Best Practices.
- **چرا مهم است:** امتیاز Lighthouse با رتبه‌بندی و تجربه واقعی کاربر همبستگی دارد.
- **مراحل:**
  1. هر صفحه را در Chrome DevTools → تب Lighthouse باز کنید.
  2. ممیزی را هم برای موبایل و هم دسکتاپ اجرا کنید.
  3. هر مورد SEO/Accessibility با امتیاز زیر ۹۰ را اصلاح کنید.
- **ابزارهای پیشنهادی:** Chrome DevTools Lighthouse، [PageSpeed Insights](https://pagespeed.web.dev/).
- **نتیجه مورد انتظار:** امتیاز SEO برابر ۱۰۰ و Performance/Accessibility بالای ۹۰.

### - [ ] ۳.۲ Core Web Vitals
- **هدف:** اطمینان از اینکه LCP، CLS و INP در آستانه "خوب" گوگل قرار دارند.
- **چرا مهم است:** Core Web Vitals یک سیگنال تایید‌شده رتبه‌بندی گوگل است.
- **مراحل:**
  1. داده‌های میدانی را در گزارش Core Web Vitals سرچ‌کنسول بررسی کنید (نیازمند ترافیک واقعی).
  2. داده‌های آزمایشگاهی را در PageSpeed Insights متقاطع بررسی کنید.
  3. هدف: LCP کمتر از ۲.۵ ثانیه، CLS کمتر از ۰.۱، INP کمتر از ۲۰۰ میلی‌ثانیه.
- **ابزارهای پیشنهادی:** Search Console، PageSpeed Insights، Chrome UX Report.
- **نتیجه مورد انتظار:** هر سه آدرس پس از تجمیع ترافیک کافی، رتبه "خوب" بگیرند.

### - [ ] ۳.۳ PageSpeed Insights
- **هدف:** دریافت داده‌های ترکیبی آزمایشگاهی + میدانی همراه با پیشنهادهای مشخص اصلاحی.
- **چرا مهم است:** مشکلاتی مانند منابع مسدودکننده رندر، اندازه تصاویر و بارگذاری فونت را آشکار می‌کند.
- **مراحل:**
  1. `https://jollypanda.ir/` را در [pagespeed.web.dev](https://pagespeed.web.dev/) بررسی کنید.
  2. هر "Opportunity" (مثل CSS استفاده‌نشده، اندازه تصویر) را برطرف کنید.
  3. پس از اصلاح، دوباره تست کنید.
- **ابزارهای پیشنهادی:** PageSpeed Insights.
- **نتیجه مورد انتظار:** امتیاز سبز (۹۰+) هم در موبایل و هم دسکتاپ.

## ۴. آنالیتیکس و انطباق قانونی

### - [ ] ۴.۱ راه‌اندازی Google Analytics (اختیاری)
- **هدف:** ردیابی بازدیدکنندگان، منابع ترافیک و رفتار کاربران.
- **چرا مهم است:** بدون آنالیتیکس، هیچ دیدی نسبت به تاثیر واقعی کار سئو وجود نخواهد داشت.
- **مراحل:**
  1. یک پراپرتی GA4 در [analytics.google.com](https://analytics.google.com/) بسازید.
  2. تگ GA4 (یا Google Tag Manager) را به همه صفحات اضافه کنید.
  3. پراپرتی GA4 را به Search Console متصل کنید تا گزارش‌ها ترکیب شوند.
- **ابزارهای پیشنهادی:** Google Analytics 4، Google Tag Manager.
- **نتیجه مورد انتظار:** داده بازدیدکنندگان بلادرنگ در GA4 ظرف چند دقیقه پس از افزودن تگ.

### - [ ] ۴.۲ بنر کوکی (در صورت نیاز)
- **هدف:** انطباق با الزامات اخذ رضایت در صورت استفاده از کوکی‌های آنالیتیکس/تبلیغاتی و انتظار بازدیدکننده از اتحادیه اروپا/بریتانیا.
- **چرا مهم است:** عدم رعایت GDPR/ePrivacy در صورت هدف‌گیری آن مناطق ریسک قانونی دارد.
- **مراحل:**
  1. مشخص کنید آیا کوکی‌های GA4/بازاریابی استفاده خواهند شد — در غیر این صورت می‌توان از این مورد صرف‌نظر کرد.
  2. در صورت استفاده، بنر رضایتی اضافه کنید که کوکی‌های غیرضروری را تا زمان تایید مسدود کند.
  3. مبنای قانونی و مدت نگهداری داده را در صفحه سیاست حریم خصوصی مستند کنید.
- **ابزارهای پیشنهادی:** [Cookiebot](https://www.cookiebot.com/)، [Osano](https://www.osano.com/) یا یک بنر سفارشی سبک.
- **نتیجه مورد انتظار:** هیچ کوکی غیرضروری پیش از رضایت اجرا نشود؛ لینک صفحه سیاست در فوتر باشد.

## ۵. دامنه و زیرساخت

### - [ ] ۵.۱ پیکربندی دامنه
- **هدف:** اطمینان از اشاره صحیح `jollypanda.ir` به سرویس‌دهنده میزبانی.
- **چرا مهم است:** پیکربندی نادرست DNS می‌تواند کل سایت را مسدود کند یا باعث قطعی متناوب شود.
- **مراحل:**
  1. مطمئن شوید رکوردهای A/AAAA یا CNAME به سرویس‌دهنده میزبانی اشاره دارند.
  2. انتشار (propagation) را در [whatsmydns.net](https://www.whatsmydns.net/) بررسی کنید.
  3. یک TTL معقول (مثلاً ۳۶۰۰ ثانیه) برای انعطاف در آینده تنظیم کنید.
- **ابزارهای پیشنهادی:** whatsmydns.net، پنل DNS ثبت‌کننده دامنه.
- **نتیجه مورد انتظار:** دامنه در سطح جهانی به سرور صحیح resolve شود.

### - [ ] ۵.۲ بررسی HTTPS
- **هدف:** اطمینان از فعال بودن گواهی معتبر و خودتمدیدشونده SSL/TLS.
- **چرا مهم است:** HTTPS یک فاکتور رتبه‌بندی است و برای اعتماد کاربر و Web App Manifest ضروری است.
- **مراحل:**
  1. مطمئن شوید `https://jollypanda.ir` با قفل معتبر و بدون هشدار محتوای مختلط بارگذاری می‌شود.
  2. در صورت پشتیبانی میزبان، HSTS را فعال کنید.
  3. تمدید خودکار (Let's Encrypt یا مدیریت‌شده توسط میزبان) را تنظیم و تاریخ انقضا را بررسی کنید.
- **ابزارهای پیشنهادی:** [SSL Labs Test](https://www.ssllabs.com/ssltest/)، DevTools مرورگر.
- **نتیجه مورد انتظار:** نمره A یا بالاتر در SSL Labs، بدون گواهی منقضی یا خودامضا.

### - [ ] ۵.۳ ریدایرکت WWW / non-WWW
- **هدف:** سرویس‌دهی سایت از یک هاست کنونیکال واحد برای جلوگیری از محتوای تکراری.
- **چرا مهم است:** موتورهای جستجو ممکن است `www.` و غیر-`www` را دو سایت جدا در نظر بگیرند و سیگنال رتبه‌بندی را پخش کنند.
- **مراحل:**
  1. هاست کنونیکال را مشخص کنید (این پروژه از غیر-`www` استفاده می‌کند: `jollypanda.ir`).
  2. یک ریدایرکت ۳۰۱ از `www.jollypanda.ir` به `jollypanda.ir` پیکربندی کنید.
  3. ریدایرکت را با `curl -I https://www.jollypanda.ir` بررسی کنید.
- **ابزارهای پیشنهادی:** curl، قوانین ریدایرکت سرویس‌دهنده میزبانی.
- **نتیجه مورد انتظار:** فقط یک ریدایرکت ۳۰۱، بدون زنجیره یا حلقه ریدایرکت.

### - [ ] ۵.۴ بررسی آدرس کنونیکال
- **هدف:** اطمینان از اینکه تگ `<link rel="canonical">` هر صفحه دقیقاً با آدرس زنده خودش مطابقت دارد.
- **چرا مهم است:** از جریمه محتوای تکراری جلوگیری می‌کند و سیگنال‌های رتبه‌بندی را متمرکز می‌کند.
- **مراحل:**
  1. سورس هر صفحه را ببینید و مطمئن شوید تگ canonical دقیقاً با آدرس ارائه‌شده (پروتکل، هاست، اسلش پایانی) یکسان است.
  2. گزارش "Page indexing" در Search Console را برای ناهماهنگی canonical بررسی کنید.
- **ابزارهای پیشنهادی:** View Source، Google Search Console.
- **نتیجه مورد انتظار:** هیچ تعارض canonical گزارش نشود.

## ۶. داده‌های ساختاریافته و دارایی‌ها

### - [ ] ۶.۱ اعتبارسنجی داده‌های ساختاریافته
- **هدف:** اطمینان از بدون خطا بودن JSON-LD مربوط به Organization، WebSite، Person، WebPage و BreadcrumbList.
- **چرا مهم است:** داده ساختاریافته معتبر امکان نمایش نتایج غنی (سایت‌لینک، پنل دانش) را فراهم می‌کند.
- **مراحل:**
  1. هر صفحه را در [Google Rich Results Test](https://search.google.com/test/rich-results) تست کنید.
  2. JSON-LD خام را در [Schema.org Validator](https://validator.schema.org/) اعتبارسنجی کنید.
  3. پیش از استقرار، هر خطا یا هشداری را اصلاح کنید.
- **ابزارهای پیشنهادی:** Rich Results Test، Schema.org Validator.
- **نتیجه مورد انتظار:** صفر خطا؛ همه انواع اسکیما به‌درستی شناسایی شوند.

### - [ ] ۶.۲ بهینه‌سازی تصاویر
- **هدف:** اطمینان از اندازه مناسب، فشرده‌سازی و ارائه تصاویر با فرمت‌های مدرن.
- **چرا مهم است:** تصاویر معمولاً بزرگ‌ترین سهم را در وزن صفحه و LCP دارند.
- **مراحل:**
  1. در صورت امکان، تصاویر عکاسی‌شده را به WebP تبدیل کنید؛ فرمت PNG را فقط در صورت نیاز به شفافیت نگه دارید.
  2. مطمئن شوید تصاویر پایین صفحه دارای `loading="lazy"` هستند (در حال حاضر روی عکس‌های تیم و تصاویر ثانویه ماسکات اعمال شده).
  3. مطمئن شوید هر `<img>` دارای `alt` معنادار است (تصاویر تزئینی می‌توانند `alt=""` داشته باشند).
- **ابزارهای پیشنهادی:** [Squoosh](https://squoosh.app/)، ImageMagick، پنل Network در DevTools مرورگر.
- **نتیجه مورد انتظار:** هیچ تصویری بیش از حدود ۲۰۰ کیلوبایت نباشد؛ وزن کل تصاویر صفحه به حداقل برسد.

### - [ ] ۶.۳ بررسی فاوآیکون
- **هدف:** اطمینان از نمایش صحیح فاوآیکون‌ها در مرورگرها، تب‌ها، بوکمارک‌ها و نصب روی صفحه اصلی موبایل.
- **چرا مهم است:** فاوآیکون گمشده یا خراب، غیرحرفه‌ای به‌نظر می‌رسد و به شناخت برند در نتایج جستجو و تب‌ها آسیب می‌زند.
- **مراحل:**
  1. بررسی کنید `favicon.ico`، `favicon.svg`، ۱۶×۱۶، ۳۲×۳۲، apple-touch-icon و آیکون‌های Android Chrome همگی با `200 OK` بارگذاری می‌شوند.
  2. نمایش آن‌ها را در Chrome، Safari و هنگام افزودن به صفحه اصلی اندروید/آی‌اواس تست کنید.
  3. آیکون‌های `manifest.json` را در Chrome DevTools → Application → Manifest اعتبارسنجی کنید.
- **ابزارهای پیشنهادی:** [بررسی‌کننده RealFaviconGenerator](https://realfavicongenerator.net/favicon_checker)، Chrome DevTools.
- **نتیجه مورد انتظار:** آیکون برند یکسان در هر بستر.

## ۷. تضمین کیفیت

### - [ ] ۷.۱ بررسی لینک‌های خراب
- **هدف:** شناسایی لینک‌های داخلی/خارجی مرده پیش و پس از راه‌اندازی.
- **چرا مهم است:** لینک‌های خراب به تجربه کاربری و کارایی خزش آسیب می‌زنند و بودجه خزش را هدر می‌دهند.
- **مراحل:**
  1. یک بررسی کامل سایت با ابزار link checker اجرا کنید.
  2. هر خطای ۴۰۴ را برطرف یا حذف کنید و لینک‌های خارجی قدیمی (مثل پروفایل‌های لینکدین) را به‌روز کنید.
  3. پس از هر به‌روزرسانی محتوا، دوباره اجرا کنید.
- **ابزارهای پیشنهادی:** [W3C Link Checker](https://validator.w3.org/checklink)، Screaming Frog SEO Spider.
- **نتیجه مورد انتظار:** صفر لینک خراب گزارش شود.

### - [ ] ۷.۲ تست دسترس‌پذیری (Accessibility)
- **هدف:** اطمینان از قابل استفاده بودن سایت با صفحه‌خوان‌ها، ناوبری فقط با کیبورد و انطباق با WCAG 2.1 AA.
- **چرا مهم است:** دسترس‌پذیری هم یک ملاحظه قانونی و هم یک سیگنال Lighthouse/سئو است.
- **مراحل:**
  1. یک ممیزی خودکار (axe یا Lighthouse Accessibility) اجرا کنید.
  2. به‌صورت دستی با کلید Tab در هر صفحه حرکت کنید تا ترتیب فوکوس و وضعیت‌های قابل‌مشاهده فوکوس بررسی شود.
  3. کلید زبان و منوی ناوبری را با صفحه‌خوان (VoiceOver/NVDA) تست کنید.
- **ابزارهای پیشنهادی:** [axe DevTools](https://www.deque.com/axe/devtools/)، Lighthouse، NVDA/VoiceOver.
- **نتیجه مورد انتظار:** بدون تخلف بحرانی/جدی axe.

### - [ ] ۷.۳ قابلیت استفاده در موبایل
- **هدف:** اطمینان از عملکرد مناسب سایت روی صفحه‌های کوچک و دستگاه‌های لمسی.
- **چرا مهم است:** گوگل از ایندکس موبایل-محور استفاده می‌کند — تجربه موبایل مبنای رتبه‌بندی است.
- **مراحل:**
  1. گزارش Mobile Usability سرچ‌کنسول را پس از ایندکس بررسی کنید.
  2. نقاط لمسی، کلید زبان و دکمه منوی موبایل را به‌صورت دستی روی یک دستگاه واقعی تست کنید.
  3. مطمئن شوید در breakpointهای رایج (۳۶۰ تا ۷۶۸ پیکسل) اسکرول افقی یا هم‌پوشانی متن وجود ندارد.
- **ابزارهای پیشنهادی:** Google Search Console، پنل device toolbar در Chrome DevTools، یک گوشی واقعی.
- **نتیجه مورد انتظار:** صفر مشکل قابلیت استفاده در موبایل گزارش شود.

## ۸. برند و حضور بیرون از سایت

### - [ ] ۸.۱ تکمیل پروفایل‌های شبکه‌های اجتماعی
- **هدف:** حفظ یکپارچگی حضور برند در همه جایی که استودیو قابل کشف است.
- **چرا مهم است:** یکپارچگی نام/آدرس/توضیح (NAP) در پروفایل‌ها، شناخت موجودیت (entity) را برای موتورهای جستجو تقویت می‌کند.
- **مراحل:**
  1. مطمئن شوید هر پروفایل فعال به `https://jollypanda.ir/` لینک می‌دهد.
  2. از همان لوگو، توضیح و کلمات کلیدی (Game Development Studio، HTML5 Games، Playable Ads و غیره) در همه پروفایل‌ها استفاده کنید.
  3. با فعال‌شدن هر پروفایل، آدرس آن را به آرایه `sameAs` اسکیمای Organization اضافه کنید.
- **ابزارهای پیشنهادی:** بازبینی دستی پروفایل‌ها.
- **نتیجه مورد انتظار:** برندینگ یکپارچه و لینک‌های کارآمد در هر پروفایل فعال.

### - [ ] ۸.۲ بهینه‌سازی صفحه شرکتی لینکدین
- **هدف:** لینکدین کانالی قدرتمند برای اعتماد B2B و جذب نیرو است.
- **چرا مهم است:** صفحه شرکتی کامل، قابلیت کشف و اعتبار را نزد مشتریان/شرکای بالقوه بهبود می‌دهد.
- **مراحل:**
  1. آدرس صفحه شرکتی، لوگو، تصویر کاور و توضیحات را با کلمات کلیدی استودیو تنظیم کنید.
  2. پروفایل شخصی هر عضو تیم را به‌عنوان کارمند صفحه لینک دهید.
  3. راه‌اندازی سایت را به‌عنوان یک به‌روزرسانی شرکتی منتشر کنید.
- **ابزارهای پیشنهادی:** LinkedIn Company Pages.
- **نتیجه مورد انتظار:** صفحه کاملاً تکمیل‌شده با اعضای تیم به‌عنوان کارمند.

### - [ ] ۸.۳ بهینه‌سازی مخزن گیت‌هاب
- **هدف:** در صورت عمومی بودن سورس، خود مخزن هم قابل کشف و حرفه‌ای باشد.
- **چرا مهم است:** یک مخزن عمومی مرتب هم به‌عنوان نمونه‌کار و هم سیگنال اعتبار فنی عمل می‌کند.
- **مراحل:**
  1. توضیح مخزن، لینک وب‌سایت و تگ‌های موضوعی مرتبط (مانند `html5-games`، `game-studio`، `seo`) را اضافه کنید.
  2. تصویر پیش‌نمایش اجتماعی (Settings → Social Preview) را اضافه کنید.
  3. مطمئن شوید فایل LICENSE با کپی‌رایت "تمامی حقوق محفوظ است" که در README ذکر شده هم‌خوانی دارد.
- **ابزارهای پیشنهادی:** تنظیمات مخزن گیت‌هاب.
- **نتیجه مورد انتظار:** مخزن دارای توضیح، تگ موضوعی و کارت پیش‌نمایش اجتماعی مناسب باشد.

### - [ ] ۸.۴ بهبود README
- **هدف:** به‌روز نگه‌داشتن README همزمان با تکامل ساختار سئو/دارایی‌ها.
- **چرا مهم است:** README قدیمی مشارکت‌کنندگان را گمراه می‌کند و برای بازدیدکنندگان نگهداری‌نشده به‌نظر می‌رسد.
- **مراحل:**
  1. بخش ساختار پروژه را به‌روز کنید تا شامل `/docs`، `manifest.json`، `robots.txt`، `sitemap.xml` و `/assets/social` باشد.
  2. یک بخش کوتاه "سئو و دارایی‌ها" اضافه کنید که به این چک‌لیست لینک بدهد.
  3. پس از هر تغییر ساختاری در مخزن، دوباره بازبینی کنید.
- **ابزارهای پیشنهادی:** ویرایش دستی، پیش‌نمایش Markdown.
- **نتیجه مورد انتظار:** README به‌درستی ساختار زنده مخزن را منعکس کند.

- **ابزارهای پیشنهادی:** branch protection گیت‌هاب، امکانات پشتیبان‌گیری سرویس‌دهنده میزبانی.
- **نتیجه مورد انتظار:** یک فرآیند بازیابی مستند و تست‌شده.

- **چرا مهم است:** محتوای تازه و مرتبط یکی از قوی‌ترین سیگنال‌های بلندمدت رتبه‌بندی است.
